# CSP · Character Skill Producer（v3.0 合并版 SOP）

> 把二次元角色变成可运行的 agent 行为包。不是角色卡，不是设定集，是可执行的行为程序。
> 本文件合并了：①通用机制标准（蒸馏科学/质检三层对账，原 SKILL_V2 v2.2）②批次执行层
> （命令持久化/爬取/清洗/蒸馏/门禁/行为闭环/批次管理，原 game-layer SOP v2.1-v2.2）。
> 历史备份：SKILL_V2.backup-v2.1.10 / SKILL_V2.backup-v2.2；各游戏专属渠道实测结论仍在
> examples/<游戏>/CSP/SKILL.md 与 examples/原神/SOP.md 中，作为本文件的补充层。

# 第 A 部分 · 核心理念与品味

CSP 做的不是复制角色台词，而是**蒸馏角色的行为操作系统**。

一个好的角色 Skill 应该回答：

- 她在不同情境下**如何反应**？
- 她的话**怎么说出来**？
- 她**怎么理解**别人的意图？
- 她在价值冲突时**先保什么、牺牲什么**？
- 她**绝对不会**做什么？
- 她的资料覆盖到哪一天，之后的新剧情如何更新？

关键区分：捕捉的是 HOW she behaves，不是 WHAT she said。标签是给人看的，行为规则是给 AI 执行的。

六层结构，缺一层就不算完成：

| 层 | 问题 | 失败时的样子 |
|---|---|---|
| 行为镜片 | 她先注意什么、忽略什么？ | 只会复述设定 |
| 反应规则 | 什么情境下靠近、逃开、攻击、沉默？ | 所有问题都同一种语气 |
| 表达 DNA | 句长、停顿、敬语、自称、情绪泄露如何组合？ | 只贴口癖 |
| 关系算法 | 她如何判断善意、背叛、亲近、利用？ | 对所有用户都一样热情 |
| 决策底线 | 价值冲突时先保什么、牺牲什么？ | 角色被用户轻易说服 |
| 诚实边界 | 哪些不知道、哪些过期、哪些只是推测？ | 硬编新剧情 |

关键原则：写得进去的是行为程序，写不进去的才保留为边界。角色的神秘感不是靠含糊制造，而是靠承认资料、视角和推断能力的限制。

## 品味守则

| 原则 | 一句话 |
|---|---|
| 行为 > 形容词 | 描述「做什么」而非「是什么」 |
| 证据 > 印象 | 重要结论必须可追溯到场景和来源 |
| 矛盾 > 一致 | 保留矛盾，这是深度的来源 |
| 语境 > 台词 | 每句经典台词必须说明场景 |
| 时间边界 > 硬拗 | 资料过期时承认边界并进入更新 |
| 口语 > 文章 | Skill 输出的是角色说话，不是论文 |
| 人味 > 完美 | 角色可以不确定、前后矛盾、沉默 |

绝不做：

- 用萌属性标签取代行为描述；
- 编造角色在原作中没说过的话；
- 把角色写成完美人设；
- 在信息不足时强行生成；
- 用知乎、微信公众号、百度百科做来源；
- 忽略资料检索日期；
- 用户指出新剧情时硬拗旧设定；
- 让游戏模板变量、系统旁白、其他角色的档案内容混入产出；
- 交付含空占位段的文件；
- 用引文堆砌和档案复述冒充行为蒸馏。

# 第 B 部分 · 批次第零层：命令持久化

- 批次开工前建 `examples/<游戏>/TASK.md`：**用户命令逐字记录**（含截图描述）→ 按本 SOP 解析成任务定义表 → 批次顺序约定 → 状态勾选；
- 后续追加命令同样逐字补录（含日期）。任何会话接手先读 TASK.md + 本文件；
- 用户追加指令随时插队（「蒸馏XX」置顶）。

## 需求确认（Phase 0）

确认：角色名称（中/日/英均可）；作品全名与时间线；生成范围（默认全面画像，不做轻量版）；用户是否有官方材料（有则最高优先）；是否跨媒体角色（默认触发跨媒体规则）。

**并判定形象结构类型（形象版本规则）**（写入 manifest 的 `character_form_type`，判定理由写进 research/01）：

### 类型 A：版本覆盖型（`versioned`）

角色发生过形态/性格/身份的更替。规则：

1. **当前版本性格覆盖旧版本**，作为默认反应模式的唯一来源；
2. 旧版本整体降级为**记忆层**，三层隔离：事实层（被问到能讲能答）/ 身份层（不以旧身份自居）/ 语言行为层（旧口癖习惯不泄漏进现在的反应）。

### 类型 B：并存形态型（`coexisting`）

同一角色同时维持多个活跃形象。规则：不做版本覆盖，改用**归因边界**——本人/各形态/扮演对象/冒名者的第一人称记忆互不混流；每形态单独蒸馏并标注触发语境；一个形态的口癖不得串入另一形态的输出。

### 类型 C：单一形象型（`single`，默认）

按行为权重分层蒸馏：反复多次出现 → 默认反应主体；偶尔出现 → 挂显式触发条件（「仅当 XX 情境时」），禁止默认触发；无法确定频次 → 降级低置信度观察。

用户只说「就做 XX」时默认全面画像并推进；同名歧义必须询问。用户没指定角色、只想「聊聊/要个推荐」时属于选角层，不进本流程。

# 第 C 部分 · 语料爬取与检索

## 渠道注册表（单一事实源）

可用检索渠道以 `references/channel-registry.json` 为准（端点、脚本、优先级、实测状态、适用作品范围），`source_search.py` 调度时按其过滤：未登记的渠道会被拒绝，`disabled`/`excluded` 渠道跳过并记录。因此：

- 禁止凭记忆假设渠道存在或可用；
- 新作品开批次前，必须先在注册表登记渠道（端点/脚本/优先级/适用范围）方可开始采集；
- 渠道实测后更新 `status`（verified/available/disabled/excluded），失败原因与**站点数据形态实测结论**写进 `notes`；
- 本文件与各游戏 SOP 不复制渠道清单，统一引用注册表。

核心本地检索入口：

```bash
python scripts/source_search.py "角色名" --work "作品名" --mode discover
python scripts/moegirl_api.py "角色名" --intro | --full | --search | --wikitext
```

## 爬什么（批次全集，一个不漏）

- 角色页全套：`avatar/{id}`（资料+其他：服装/名片/特色料理）、`avatarFetter/{id}`（角色故事+语音文字版）、`furniture/{furnitureId}`（Companion 尘歌壶对话）；
- **全类型任务对话**：站点 Travel Log 下拉的全部五类——Archon(aq) / Story(lq) / Event(eq) / World(wq) / **Commissions(iq，每日委托)**——一个不漏；类型代码以 JS/i18n 实测为准（下拉名和代码会不一致）；
- 特殊主体（多主角作品的「正主/另一胞胎」）：做专项分离切片，两份 skill 不得互串。

## 数据结构先实测再写爬虫

分支=对话链里的 `MultiDialog` 节点（每选项独立后继链）；旁白=`narratorData`（role 为空，须与台词隔离）；role 为空的一般=玩家发言。每条实测规律写进渠道 notes。

## 断点续跑

按 `{id}.json` 存在性跳过，增量抓新版本任务零成本。

## 落盘三层

`raw/`（原始 JSON，**永不修改**，审计底稿）→ `digest/`（每角色台词±N行切片，蒸馏主料）→ `quest_text/`（命中任务全文含分支标注，审计用）。三层都 gitignore。

## 信息源优先级

| 优先级 | 来源 |
|---|---|
| 最高 | 用户提供的官方材料（设定集、访谈原文、BD 特典、官方字幕、截图、游戏剧情文本）；官方文本仓库（如 Kengxxiao/ArknightsGameData 类） |
| 高 | 官方网站、官方角色介绍、官方剧情文本；萌娘百科、Wikipedia、作品 Fandom Wiki |
| 中 | Bangumi、AniDB、游戏数据库、Bilibili 高质量专栏、ANN |
| 低 | 粉丝讨论、社区解读（必须标注为推测） |
| 排除 | 知乎、微信公众号、百度百科 |

重要结论至少需要两个独立来源。来源冲突时保留冲突，不要强行调和。

## 检索失败规则

关键网站不能因一次失败就标「信息不足」。必须记录：尝试的命令、查询词和 resolved title、URL、错误信息、替代来源、对可信度的影响。最终仍失败时在 sources.json 中记录，status=failed。

## 语料清洗禁令（入库前逐条过检）

官方文本语料入库与引用前必须清洗：

1. **变量过滤**：`{@nickname}`、`{player_name}` 等模板变量不得出现在任何产出文件，一律替换为规范称呼。清洗必须**对齐站点前端渲染逻辑**（逆向其 JS 文本管线）：M/F 性别变体取站点默认、RUBY/LINK 取正文、未知大写宏删除并计数，派生后验证残留=0；
2. **旁白隔离**：系统叙述文本（第二人称指令、场景描写旁白）标【旁白】隔离，不得作为角色台词收录；经典台词必须是角色第一人称发言；
3. **跨角色校验**：每条引用必须核验说话者/描述对象确为该角色；档案字段引用必须与该角色对应，禁止整块复制角色表；
4. **交叉注入门槛**：外部交叉来源（萌百/BWIKI 等百科）只有提供官方来源没有的增量信息时才可注入，且必须标注 tier 与冲突处理规则；百科定义句、首句 stub 不得作为「侧写」引用。（原神批次实际未启用外部百科——gi.yatta.moe 官方数据已覆盖全部所需维度，所有 skill 的 sources.json 仅含官方来源；此项是跨作品批次遇官方数据缺口时的备用规则。）
5. **已知失效模式（实测踩坑）**：文本风格病态的语料（大量省略号、电报体、谜语人写作）蒸出的表达质感会复读该病态——禁用或强制降级；角色被他人以完全无关的外号称呼时，必须先统一为本名/常用简称再入库；与角色无关联的长段整段丢弃，不做「顺手保留」；
6. 清洗结果记入 `references/quality-report.json` 的 `corpus_cleaning` 字段。

**批次清洗附加规则**：清洗发生在派生层，raw 永远原样；分支渲染必须**节点级去重**（共享后文只渲染一次并标注），否则顺序分支会把共享后文指数级重复（实测膨胀 2700 倍）。

# 第 D 部分 · 生成目录结构与 manifest

```text
<character-slug>/
├── SKILL.md
├── manifest.json
└── references/
    ├── sources.json
    ├── distillation.md
    ├── quality-report.json
    ├── behavior-report.json
    └── research/
        ├── 01-setting.md
        ├── 02-personality.md
        ├── 03-expression.md
        ├── 04-relationships.md
        ├── 05-key-scenes.md
        └── 06-media-coverage.md（跨媒体角色必写；普通角色可省，信息入 manifest）
```

Skill 必须自包含，复制整个目录就能独立使用。研究文件不完整时不得声称生成完成。

## 运行时单文件原则

- 运行时只依赖 SKILL.md 一个文件；禁止「详见 references/xxx」这类运行时依赖引用；
- references/ 是溯源审计材料，只在生成与更新时使用；
- SKILL.md 中的来源信息收敛为**一行声明**（检索日期+来源数+覆盖范围），完整 URL 清单只放 sources.json；
- **长度下限制（宁多勿少）**：不设字数上限；只设四条下限——行为模式 ≥10 条且逐条含完整三元组、表达质感标记 ≥4 类、行为示例总量 = 模式数 × 3（≥10 模式即 ≥30 例）且每条行为模式 ≥3 个示例、诚实边界 ≥3 条。为省篇幅压缩例子=违规。

## manifest.json 必填字段

```json
{
  "schema_version": "2.0",
  "name": "character-slug",
  "character": "角色名",
  "work": "作品名",
  "character_form_type": "versioned | coexisting | single",
  "aliases": [],
  "generated_at": "YYYY-MM-DD",
  "research_started_at": "YYYY-MM-DD",
  "research_completed_at": "YYYY-MM-DD",
  "latest_source_checked_at": "YYYY-MM-DD",
  "covered_until": {"date": "YYYY-MM-DD", "description": "…"},
  "covered_media": [],
  "not_covered": ["YYYY-MM-DD 后发布的新剧情、新活动、新访谈、新设定修订"],
  "source_count": 0,
  "source_tiers": {},
  "evidence_density": "normal",
  "quality_score": null,
  "honesty_boundary": "",
  "csp_version": "2.0"
}
```

`csp_version` 必填实际版本号，禁止留 unknown。`evidence_density` 必填：single_source / sparse / normal。每条来源记录：id、source、title、url、source_tier、officiality、media_type、retrieved_at、content_hash（能算则算）、status、warnings。失败来源也要记录。sources.json 记录键为 **`records`**。

## 时间边界规则

SKILL.md 必须包含以下指令段（日期由 manifest 填充）：

```text
你的知识截止于 {covered_until.date}。当用户提到该日期之后的内容时，按以下三种情况处理：
1. 用户把该日期之后的内容当作既定剧情陈述，且与本角色相关 → 不得否认、不得顺着编造，使用标准回应：
   「我的资料更新至 {covered_until.date}，可能没有覆盖之后发布的内容。
    如果你提供新剧情/新资料，我可以帮你更新这个 Skill；这可能会消耗一些 Token。」
2. 用户要求想象/推演/创作该日期之后的场景 → 不触发标准回应，按已蒸馏的行为模式推断，且不断言。
3. 用户提到该日期之前、但本 Skill 资料中不存在的旧剧情 → 走知识边界规则：承认不知道，不编造。
```

# 第 E 部分 · 逐角色蒸馏（Phase 1-7）

## 来源索引（P1-P2）

sources.json 预置官方来源+内容哈希，**键名用 `records`**；禁止蒸馏期新增未实测来源。

## 五维调研（P3-P4）

启动 5 个并行子 agent（维度缺口明确时再外部补搜）：

| Agent | 重点 | 输出 |
|---|---|---|
| 1 设定 | 基本信息、世界观、身份、时间线、媒体覆盖 | 01-setting.md |
| 2 性格 | 行为模式、压力反应、内在矛盾、成长弧 | 02-personality.md |
| 3 表达 | 句式、词汇、自称、敬语、口癖、台词语境 | 03-expression.md |
| 4 关系 | 重要关系、社会认知、跨作品互动 | 04-relationships.md |
| 5 名场面 | ≥8 个关键场景、决策逻辑、压力行为 | 05-key-scenes.md |

每个研究文件必须写：使用的 source id 或 URL、可信度、官方设定/wiki 汇总/用户材料/粉丝推测的区分、冲突点、检索失败与降级情况。**场景标题必须 `## 场景N：` 开头**（行为测试出题器靠它解析）。

批量模式允许单 agent 依次产出六件套（并发预算让给行为测试侧），但五维内容要求不变。

采集完成后执行**语料清洗禁令**五检（见第 C 部分），不合格语料退回处理。

## 跨媒体覆盖（P4）

跨媒体角色必须写 06-media-coverage.md：已覆盖媒体、未覆盖媒体、主线和衍生材料的权重、不同媒体冲突、本 Skill 采用的时间线、截至哪个日期。游戏活动、卡面故事、区域对话可作为日常行为和关系补充，但不能覆盖主线设定，除非官方明确更新。

## 调研质量检查点（P5）

运行 `python scripts/merge_research.py <skill_directory>`：每个维度来源数、总来源数、黑名单来源、失败来源、重要结论交叉验证、跨媒体覆盖、资料日期记录、**空占位段**（出现「以下行为：」却无后续=FAIL）。缺口明显时补充研究后再蒸馏。

## 行为蒸馏（P6）

读取 `references/distillation-framework.md`，按形象结构类型执行（A 版本覆盖/B 并存/C 单一分层）。核心行为模式必须回答「在什么情况下→做什么→为什么这样」，带证据链（引用 research 场景+来源 id）。

**两级蒸馏**：
- **一级：行为模式（必须，质量门槛）**——情境→行为→为什么三元组，运行时真正执行的规则。设数量下限、不设上限；
- **二级：剧情具体例子（尽量丰富，many-shot）**——具体场面与台词引用，是一级模式的证据与 few-shot 锚点：蒸馏与质检时溯源，运行时供 AI 推断原作没写过的场景。**总量 = 模式数 × 3（≥10 模式即 ≥30 例）且每条一级模式 ≥3 例**；宁多勿少，禁止为省篇幅砍例子。每条二级例子必须写进 SKILL.md 正文随文件整体加载。

**生成纪律**：
- **剧情均匀性 + 主导特征优先**：取材跨版本/篇章均匀——任一任务来源占比 ≤60%、来源桶 ≥4（scene_source_spread 强制）；先判定主导特征，置首、示例数并列最高；distillation.md 显式声明主导特征及理由；
- **相似度防线**：与已有角色 Skill 只对比「行为动态+表达质感」两章、排除共享模板段；双信号（字符 3-gram 抓复制 + 序列比对抓改写）取最大值。阈值 0.2 双侧校准（阴性 244 skill/29554 对 max=0.164；阳性三级抄袭 0.960/0.763/0.466 全命中）；超标仅列 needs_human_review，永不自动 FAIL；逐句重写低于阈值属已知盲区，防线在溯源审计；
- **选例三标准**（每例至少满足一条）：① 本角色专属专有名词 ② 第一人称原话引用 ③ 换角色该场面不成立（③由 judge 与人工把关，①②机器强制）；每例挂锚点行（`> 锚点：05-key-scenes.md#场景标题` 或 `> 锚点：行为动态·规则名`），存在性由 example_anchor_check 强制；
- 证据必须**具体到可指认**：真实引句、原话、具体场景，区分「剧情明说」vs「合理推断」（推断必须显式标注）；
- 字段语义自检：「核心动机」必须能回答「她为什么而行动」，头衔职级描述不是动机；
- **反向排除**：语料不支持的常见模板人设显式禁写；
- 只过一重验证的行为降级低置信；**矛盾保留，不抹平**。

**单源降级阶梯**：某维度来源 <2 → 该维度全部结论强制低置信并记入质检报告；核心行为模式无法双源支撑 → 允许**拒绝生成**该 Skill（写明补充什么材料可解锁）；manifest 写 evidence_density（single_source/sparse/normal）。这是保底规则，不是降低标准的借口。

**长文本加工路径**：几十万字剧本/小说不直接塞调研 agent——先 `corpus_slicer.py <文本> --out <目录> --role <角色名>` 切 ~15k 字符片（编码兜底 text_io、结构感知断点、overlap 防腰斩）→ 逐片交**无记忆子 agent** 提证据到 `<目录>/extracted/<片号>.md` → `corpus_resume.py` 片级断点续跑（哈希核对，连败 5 次熔断，人工 unlock）→ 每片证据挂「源文件+片号」，与 wiki 证据同台过来源分级。

**语料不足的替代路径（批量实测）**：无独立档案页的角色（NPC/向导/解说员类），可从任务对话原始数据按 role 提取第一人称台词自建语料（原神派蒙实测：1073 任务 49462 条）；纯数值档案、零性格文本的角色 → 走单源降级阶梯拒绝生成。

## 蒸馏确认检查点（P7）

向用户展示：核心行为模式、表达质感、核心动机、内在矛盾、知识边界、资料覆盖日期、未覆盖媒体。用户确认后再组装。（批量授权连续生产模式可跳过逐角色确认，以抽检替代。）

# 第 F 部分 · 质量标准（2026-09-07 上调，全批次生效）

- **一级行为模式 ≥10 条**；每条模式 **≥3 个示例**；每个示例双标注：`> 锚点：`（复现例指 `05-key-scenes.md#场景名`，外推例指 `行为动态·规则名`）+ `> 规则：模式名`；
- 行为示例总量 ≥20（实际按 10×3=33 起）；表达质感 ≥4 类；诚实边界 ≥3 条；「我所不知」写成含触发词的列表项（陷阱题从这抽）；
- 证据不足走单源降级阶梯，**不得降下限凑数**。

# 第 G 部分 · 结构质检（第一层，quality_check.py）

检查项总清单以 `references/checks.yaml` 为单一事实源：文档承诺、quality_check.py 实现、`preflight_check.py` 三方对账，谁漂移谁显形；登记未实现的检查如实标 unimplemented，不得宣称全过。

原神批次踩过的 7 个坑（新批次直接对照规避）：

1. 行为动态每条模式必须含「**为什么**」行（三元组检查）；
2. 每个示例必须含第一人称原话引用（引号内须有「我」）或专属词表命中；
3. 锚点指向的内容必须真实存在；
4. 05-key-scenes 场景标题必须 `场景N：` 前缀（否则出题器解析 0 场景直接中止）；
5. 「我所不知」必须是 `- ` 列表项且含「不知道/不明/不在场」类触发词；
6. 核心动机 ≥20 字且含动机动词（想要/守护/渴望…），头衔句不算动机；
7. manifest：`csp_version` 实值 + `schema_version: "2.0"` 一致 + `evidence_density` 必填；sources.json 记录键为 `records`。

加固检查：`{@nickname}` 类变量泄漏（零容忍）、空占位段检测、SKILL.md 自包含检测、跨角色相似度（超标只列 needs_human_review，永不自动 FAIL）。

结果写入 `references/quality-report.json`。

# 第 H 部分 · 行为测试闭环（第二层，behavior_test.py）

## 出题（exam）

2 复现（从 05-key-scenes 抽，证据链强制）+ 2 外推（依行为模式出原作没写的情境）+ 1 知识边界陷阱题（从「我所不知」清单的主题段生成，**不泄漏规则原文**；无陷阱题则中止——硬门不可触发即形同虚设）。解析不出证据链直接中止——禁止凭出题者记忆出题。已知缺陷保持修复：strip/generic 突变必须连「行为示例」章节一起剥。

## 无记忆答题

全新子 agent 扮演回答，只喂「SKILL.md 正文+题目」，禁止携带 research/distillation 等蒸馏侧材料；**主 agent 不得拿自己的会话记忆答题——自演自判的报告一律作废**。

执行通道：首选 ZCode agent 通道（串行+退避重试 5-12 分钟）。~~本机 `claude -p` CLI~~（独立进程零记忆、绕开并发限流，早期实测 agent 通道 6 连败/CLI 通道 10+ 连胜）**已于 2026-09-13 起被用户明令禁止（成本原因），不得启用**；限流时以退避重试与单线串行消化。批量模式可用单 agent 连答 5 题（answer-all，零质量损失）。

## 独立 judge

输入只有题目+证据链+回答；四维（语气一致性/行为模式命中/知识边界/口癖质感）各 1-5 分锚点判分（锚点 ≥20 字引用证据），每维 ≥4 分（checks.yaml `pass_threshold_per_dim`）才通过。**装知道=整体 FAIL（知识硬门），其余三维再高也不通过**。judge 的从严备注记入 review_notes。

## 突变测试

对 SKILL.md 做 4 组规则删除/替换突变后重测：generic-reactions / remove-expression / remove-knowledge-boundary / strip-behavior-core（strip/generic 必须连「行为示例」一起剥）。judge 检不出退化=测试无效；**≥1 检出即整体有效，全未检出 → INCONCLUSIVE（不可采信）→ 须执行 A/B 对照**。已知现象：3/4 未单独检出属「冗余编码/参数化知识掩盖」。

## A/B 对照

`control` 命令生成无 skill 基线组提示词（仅角色名+作品名+题目，零 skill 内容与边界纪律），同一套题重测。贡献判定：**(A硬门过且B不过) 或 知识边界差≥2 或 总差分≥3** → skill_contribution_detected。A/B 是 INCONCLUSIVE 的规定补救，也是「底模先验覆盖」的定性工具。

## 闭环

任一维度不达标 → 定位失败维度与对应行为模式 → **只重蒸馏受影响部分** → 重测，直至过门。结果写入 references/behavior-report.json，judge 从严备注记 review_notes。

## Batch Mode（批量模式，v2.2 引入；**当前默认停用**——2026-09-15 用户指令恢复 v1.0 全量流程为标准口径，本节降级为历史存档与「语料不足/应急场景」的备选参考，新批次默认走第 E-H 部分完整流程）

触发条件：用户明确要求批量连续生产多个角色且主动要求简化。单角色精品/审计生产走全流程；本节是**经实证的等价简化**（原神 123 席实战复盘）。

**两条线结构**：
- 主线（约 3/4 角色）：research 01-05 → 蒸馏 ≤10 行 → SKILL.md（≥10 模式 × ≥3 例）→ manifest → 静态 QC 全过 → 出卷 → 入库（notes 标「抽检未测」）；
- 抽检线（约 1/4，每 4 个抽 1）：主线 + D-lite 行为链——答题（单 agent 答 5 题）→ 判卷兼收尾 agent（全新实例：独立判卷 + finalize + 台账）。

**简化项及依据**：突变改抽检每 10 角色 1 项（remove-knowledge-boundary 实证最灵敏）；A/B 全砍（不影响交付结论）；06 废除（机器只查 01-05）；蒸馏 ≤10 行；answer-all；D-lite；骨架模板化（写手只读虚构演示角色模板，禁通读真实成品）。

**不可简化项**：静态 QC 全量；判卷全新实例；K1 必须存在；规格下限不放松；突变未检出如实记「冗余」。

**运维战术（实测有效）**：并发上限 2（3 个以上触发并发限制且互杀）；限流退避 5-12 分钟；**磁盘即进度条**（45 分钟无新产出判僵死）；接力（从磁盘已有产物继续，不从头重跑）；两段式拆分缩短单 agent 存活时间；连败 3 次主会话亲自接管兜底。

**特殊口径**：语料不足→诚实 deferred（写明原因与解锁条件）；零第一人称台词→二手证言重建版（明写重建，判卷按重建口径）；名册外追加→同管线；覆盖缺口→补采样重跑。

**留痕**：模式变更写策略文件；台账逐角色 notes；抽检欠账登记+主队列完成后补抽。

# 第 J 部分 · 更新已有 Skill

触发语：「更新这个 skill」「最新剧情不是这样」「XX 出新作了」「用新版本剧情更新她」「这个设定过时了」。

1. 确认用户提供的材料与来源，按信息源优先级定级；

4. 重跑静态 QC + （如该角色已有行为报告）重跑 D-lite 或全链；
5. 台账 notes 记录更新。
